# 自定义数据源与查询参数验证结果

## 验证范围

本轮解决核心验证页中“查询参数固定、数据来源固定”的问题，完成一个主数据集的端到端闭环：

- SQL Server 数据源连接可配置，密码只写不读；
- 主数据集维护参数化只读 `SELECT/WITH` SQL；
- 查询参数可新增、删除、排序，并配置类型、来源、控件、默认表达式、必填和 URL 预填；
- 返回字段可新增、删除、排序，并配置类型、列宽和公式模板；
- 预览、普通导出和大文件导出读取同一份数据库配置；
- 保存使用配置修订号做乐观并发检查。

本轮不包含多数据集、参数级联选项、配置发布审批和历史版本回滚。

## 安全边界

- SQL 文本只接受单条 `SELECT/WITH`，拒绝注释、多语句、临时表、DML、DDL、`EXEC` 和外部数据源入口。
- SQL 中的 `@参数名` 必须有对应参数定义，运行时使用 `SqlParameter` 绑定，不拼接输入值。
- `Fixed/System` 参数拒绝客户端覆盖；参数按配置类型转换后才进入数据库命令。
- 配置读取只返回 `passwordConfigured`，不返回连接串或密码。
- 配置、连接测试、动态查询和导出入口使用 `SuppressMonitor`，不把密码、查询参数或数据结果写入 Admin.NET 请求监控日志。
- 数据源查询有连接超时、命令超时和最大行数限制。

静态 SQL 校验不是数据库权限控制的替代品。正式数据源必须使用单独的只读账号，并限制到允许查询的库、视图或存储副本。

## 上线前缺口

1. `PocReportApi` 当前仍为本地核心验证入口，类级别带 `AllowAnonymous`。正式环境必须把配置读取、保存和连接测试迁入管理员鉴权接口，并记录不含密码和查询结果的审计事件。
2. `RcDataSource.ConnectionString` 当前用于验证闭环。正式环境必须改为凭据加密或外部密钥引用，禁止普通数据库查询者读取连接凭据。
3. 当前只有 SQL Server 和一个主数据集；多数据集、主从关系、下拉选项数据集和参数级联仍未实现。
4. 配置只有当前修订号并发保护，没有草稿、发布、审批和历史回滚。上线前至少要区分“编辑中”和“已发布”。
5. 现有模板的“序号/科室”两个明细标记与表头位置相反，这是本轮之前已存在的模板数据问题，需要单独修正保存模板，不属于数据源和参数配置代码。

数据库迁移不提供自动删表回滚。若验证功能需要撤回，先停止新接口使用并导出 4 张配置表；是否删除新增表必须由数据库负责人确认，不能由应用启动流程自动执行。
