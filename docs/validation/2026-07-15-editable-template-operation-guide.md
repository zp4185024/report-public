# 可编辑报表模板操作说明

日期：2026-07-15  
验证报表：`dept-workload`（科室工作量统计）  
当前地址：`http://localhost:5175/?hospitalId=H01&deptId=D02&personId=P03`

## 1. 页面入口

打开当前地址后，页面默认进入“模板设计”模式。顶部显示模板版本和保存状态；查询区中的医院、科室、人员来自 URL，开始日期和结束日期由后台默认值初始化。

当前本地服务：

- 前端：`http://localhost:5175`
- 后端：`http://localhost:5007`
- 接口文档：`http://localhost:5007/swagger`

## 2. 编辑模板

模板区域使用 Univer OSS，常用编辑方式与电子表格一致：

1. 单击单元格后直接输入标题、文字、数字或公式。
2. 使用顶部工具栏设置字体、字号、加粗、对齐、边框、颜色和数字格式。
3. 使用公式栏查看或修改当前单元格内容。
4. 支持合并单元格、调整行高列宽、复制粘贴、撤销和重做。

修改模板后，顶部状态会从“已保存”变成“未保存”。

## 3. 绑定后台字段

左侧“模板字段”分为参数和明细两组。先选择目标单元格，再点击字段名称即可插入绑定。

参数字段：

- 医院：`{{params.hospitalId}}`
- 科室：`{{params.deptId}}`
- 人员：`{{params.personId}}`
- 开始日期：`{{params.startDate}}`
- 结束日期：`{{params.endDate}}`

参数可以与固定文字放在同一个单元格，例如：

```text
统计期间：{{params.startDate}} 至 {{params.endDate}}
```

明细字段：

- 序号：`{{detail.sequence}}`
- 科室：`{{detail.departmentName}}`
- 门诊人次：`{{detail.outpatientCount}}`
- 出院人次：`{{detail.dischargeCount}}`

明细字段必须独占单元格，并放在同一条明细模板行中。当前种子模板使用第 6 行作为明细模板行。

当前验证只允许一个明细区域。如果要在新工作表或新行重新建立明细区域，必须先删除旧区域中的全部 `{{detail.*}}` token，或者直接删除不再使用的旧工作表。普通标题、参数和公式可以继续分布在多个工作表中。发生冲突时，页面会同时显示旧区域工作表、行号以及新 token 的工作表和单元格位置。

## 4. 使用公式

公式直接写在明细模板行中。例如当前模板的 `E6` 为：

```text
=C6+D6
```

预览 20 条数据时，模板行会扩展为 20 行，公式自动变为 `E7 = C7+D7`、`E8 = C8+D8` 等相对公式，并由 Univer Web Worker 在浏览器中计算。

本轮不在模板外增加统计计算。大数据汇总后续由导出的 Excel/WPS 打开文件时根据公式计算。

## 5. 预览和分页

1. 在查询区修改医院、科室、人员或日期。
2. 点击“预览”，页面使用当前未保存的模板草稿查询后台数据。
3. 预览模式为只读，显示当前页数据、查询耗时和渲染耗时。
4. 点击“上一页”或“下一页”查询相邻页面。
5. 点击“模板设计”返回编辑模式。

预览工作簿是模板草稿的临时副本。后台数据、扩展行和公式计算结果不会反写并污染设计模板。

## 6. 保存和刷新

1. 返回“模板设计”模式。
2. 点击“保存模板”。
3. 保存成功后状态显示“已保存”，修订号增加，例如从 `revision 0` 变为 `revision 1`。
4. 刷新浏览器，数据库中保存的模板、绑定和修订号会重新加载。

如果另一个页面已经保存了新版本，当前旧页面不会覆盖它；系统会提示模板版本冲突，需要刷新后重新编辑。

## 7. 导出模板

“导出模板”用于把当前设计草稿转换为 `.xlsx`：

1. 保持在“模板设计”模式。
2. 可以先修改文字、公式或样式，不要求先保存模板。
3. 点击“导出模板”，浏览器下载 `科室工作量统计.xlsx`。
4. 导出的公式仍是 Excel 公式，由 Excel/WPS 打开文件时重新计算。

导出读取编辑器的当前草稿，不会修改数据库模板、修订号或保存状态。

## 8. 导入模板

“导入模板”用于把 `.xlsx` 作为新的设计草稿载入 Univer：

1. 点击“导入模板”并选择 `.xlsx` 文件。
2. 如果当前已有未保存修改，页面会先确认是否替换。
3. 后台完成文件上限、映射规则和 token 校验后，页面才会替换编辑器内容。
4. 成功后页面显示已导入单元格数和映射版本，并把状态标记为“未保存”。
5. 先点击“预览”核对数据和公式；确认无误后再点击“保存模板”入库。

导入成功本身不会写数据库，也不会增加 revision。导入失败时，当前草稿保持不变。

当前限制为单个文件不超过 10 MiB、最多 10 个工作表、最多 200,000 个已用单元格。已验证的双向兼容内容包括：

- 文本、数字、布尔值、日期和时间；
- A1 公式；
- 字体、字号、粗体、斜体、下划线、删除线、字体色和背景色；
- 数字格式、水平/垂直对齐、换行、旋转和四边边框；
- 合并单元格、行高、列宽、冻结区域和多工作表顺序。

Excel 错误值会按文本导入并产生兼容提示。图片、图表、批注、数据验证、条件格式和宏不属于本轮模板交换范围。

## 9. 数据库映射规则

本地验证库为：

```text
.codex-run/editable-template-validation/Admin.NET.poc.db
```

Excel 与 Univer 的字段路径、转换方式和尺寸系数保存在单表 `RcPocExchangeMapping` 中。当前 `0.25.1 / mappingVersion 1` 共 50 条记录：

- `ExcelToUniver`：25 条；
- `UniverToExcel`：25 条。

每个映射点是一条独立记录，可以按 `RuleCode` 修改和排查，不需要重新编译转换器。新增映射版本时应插入新版本记录，不直接覆盖仍在使用的旧版本。

## 10. 模板交换与数据导出

顶部“导入模板 / 导出模板”只处理模板设计，包括 token、公式、样式和布局。

普通数据导出和大文件数据导出是另一条执行链路：它们接收医院、科室、人员和日期等查询参数，按模板生成实际数据文件。两类功能不能混用；导出模板不会查询业务明细，导入模板也不会把 Excel 中的业务数据写入后台数据源。
