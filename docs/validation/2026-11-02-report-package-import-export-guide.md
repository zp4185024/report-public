# 报表包导出/导入操作指南

日期：2026-11-02
适用范围：报表中心前端（ReportWeb）「导出包」按钮与「报表导入」向导页；对应后端接口 `/api/report-center/poc/reports/{reportCode}/package` 与 `/api/report-center/poc/report-packages/*`。

## 1. 功能定位与整体流程

报表包是报表中心跨环境迁移报表的载体：一个 JSON 文件（`<reportCode>.report-package.json`），内含报表定义、参数、模板快照（Univer 工作簿）和数据集 SQL。**包内不包含数据源连接串、密码或任何业务数据。**

典型分工：

```
开发机（设计验证）                          线上环境（启用）
─────────────────────────                ─────────────────────────
AI 辅助设计报表                            上传报表包文件
  ↓                                        ↓
本地导入/建库脚本初始化                      服务端校验（结构 + 目标库冲突探测）
  ↓                                        ↓
测试数据预览、调样式、调 SQL                 选择目标数据源（记忆上次选择）
  ↓                                        ↓
模板列表 →「导出包」下载 JSON     ──传输──→   试跑（真实查询最多 50 行 / 超时 30 秒）
                                           ↓
                                          确认导入 → 打开报表工作台
```

## 2. 页面操作步骤

### 2.1 开发机：导出报表包

1. 进入「模板列表」页（`/reports`）。
2. 找到目标报表所在行，确认「模板版本」列不是「未保存」（未保存模板的行导出按钮被禁用）。
3. 点击行内「导出包」按钮（包裹图标），确认提示后浏览器下载 `<reportCode>.report-package.json`。
4. 把该 JSON 文件通过内网渠道（共享目录、运维通道等）传到线上环境。

### 2.2 线上：报表导入向导（侧边栏「报表导入」，`/report-package-import`）

**步骤 1 上传报表包**

- 点击「选择文件」或直接把 `.json` 文件拖入虚线框。
- 前端先做本地识别（packageKind / packageVersion / 必需节），明显不是报表包的文件就地提示，不会发请求。
- 本地识别通过后自动调用服务端校验并进入步骤 2。

**步骤 2 校验与目标库**

- 摘要卡展示：报表编码、报表名称、数据集、参数数量、字段数量、导出方数据源类型、包文件导出时间。
- 「校验未通过」红框逐条列出错误，存在错误时无法进入下一步，只能重新选择文件。
- 黄色「校验警告」只提示不阻断。
- 选择**目标数据源**（只列已启用且已配置密码的数据源）；选择会记忆在本机浏览器，下次进入自动带出。
- 目标数据源类型与导出方数据源类型不一致时给出醒目警告，建议务必试跑。
- 导入模式：
  - 目标库不存在同编码报表 → 可选「新建报表」或「替换现有报表」；
  - 已存在同编码报表 → 「新建」被禁用并说明原因，只能「替换」（先删旧报表再建）。
- 数据集冲突处理：
  - 不存在同编码数据集 → 提示将新建；
  - 存在且内容一致 → 提示将直接复用；
  - 存在但内容不一致 → 出现「替换数据集」复选框；若该数据集被其他报表引用，复选框禁用并说明影响，只能复用现有数据集。

**步骤 3 试跑数据**

- 按包内参数定义自动生成参数表单（文本/数字/日期/时间/月份/年份/是否/下拉/多选），固定值、默认值表达式（如 `startofmonth(today())`，按当前日期计算）、选项首项依次作为初始值；必填且无默认值的参数必须填写后才能执行。
- 「执行试跑」用目标数据源真实执行包内 SQL，展示：返回列清单、样例数据表格（可滚动）、耗时、是否被 50 行上限截断、实际列与包内字段契约的差异（警告）。
- 试跑可反复执行（修改参数或换数据源后原结论自动作废）。
- 「跳过试跑」需要二次确认；跳过意味着 SQL 方言兼容性和字段结构未经真实验证，问题会推迟到导入后使用时才暴露。

**步骤 4 确认导入**

- 摘要列出将执行的动作：数据集新建/复用/替换、报表新建/替换、目标数据源、试跑状态。
- 点击「确认导入」并二次确认后提交；服务端写入并记录审计文件。
- 成功后展示数据集/报表动作与警告，并提供「打开报表」直达该报表工作台。
- 成功后导入按钮锁定，禁止重复提交；失败时停留在本步展示后端错误，可返回修复后重试。

## 3. 安全边界

- **包内无敏感连接信息**：导出包只含业务定义；数据源连接串、密码、分享保护口令摘要均不进包。导入时由线上管理员显式选择目标数据源。
- **强制服务端校验**：本地识别只挡明显错误文件；结构校验、SQL 只读校验、编码合法性、模板绑定一致性和目标库冲突探测全部由服务端完成，errors 非空即阻断导入。
- **试跑限制**：试跑在目标数据源上真实执行包内 SQL，但只读、最多返回 50 行、超时 30 秒；行数被截断时明确提示。
- **数据集共享保护**：内容不一致的同编码数据集默认不覆盖；被其他报表引用时禁止替换，避免导入一张报表弄坏另一张报表。
- **审计**：每次导入由服务端在 `output/report-packages/` 下写审计文件（前端不接触该目录）。
- **前端不做信任决策**：导入模式、数据集替换、试跑结论都只是请求参数，最终写入规则由服务端裁决。

## 4. 注意事项

- 试跑会真实查询业务库（只读 SELECT）；生产高峰期请评估查询开销，参数尽量选小范围。
- 强烈建议不要跳过试跑，尤其是目标数据源类型与导出方不一致（如 SqlServer → Oracle）的场合。
- 分享保护口令不随包迁移：若报表在开发机开启了分享保护，线上启用后需在报表配置里重新设置口令。
- 目标数据源选择记忆在操作员本机浏览器（localStorage），换浏览器/换电脑需重新选择。
- **登录权限尚未接入**：报表包接口与现有报表接口一样是匿名可访问的全站遗留项，上线前必须按现有整改计划接入登录与权限控制，在此之前请通过网络层（内网/VLAN/防火墙）限制访问。
