# 模板公式缓存与全量数据导出设计

日期：2026-07-15  
验证报表：`dept-workload`  
适用版本：Univer OSS `0.25.1`、.NET 8

## 1. 背景与问题

当前页面已经完成 Univer 模板编辑、数据库保存、分页预览和 XLSX 模板导入导出，但实际操作暴露了两个问题：

1. XLSX 导入后，模板明细行中的公式立即显示 `#VALUE!`。
2. 页面只有“导出模板”，没有明确的“导出完成数据”入口，现有普通/大文件接口仍使用写死结构，未读取已保存模板。

公式错误不是公式文本丢失。导入结果仍包含 `f = "=C6+D6"`，但公式单元格缺少缓存结果 `v`；设计态的 `C6`、`D6` 是 `{{detail.*}}` 字符串，Univer 默认的 `WHEN_EMPTY` 初始化模式会重新计算缺少 `v` 的公式，因此得到 `#VALUE!`。

Univer 的单元格模型明确区分公式文本 `f` 与公式计算结果 `v`：

- https://docs.univer.ai/guides/sheets/model/cell-data
- https://docs.univer.ai/guides/sheets/features/core/formula

## 2. 已确认需求

### 2.1 两类导出

页面只向设计人员暴露两个主要语义：

- **导出模板**：导出设计草稿，保留参数 token、明细 token、公式、样式和布局，不查询业务数据。
- **导出数据**：读取数据库中已保存的模板，重新执行当前查询条件，导出参数和全部明细均已填充的结果文件。

普通同步导出和大文件异步导出是“导出数据”的执行策略，不作为第三种导出语义。

### 2.2 保存门禁

数据导出只能使用数据库中已保存的模板：

1. 当前模板有未保存修改，或模板仍是 `revision 0` 时，点击“导出数据”先显示保存确认。
2. 用户确认后先保存模板，后台返回新 revision，再开始数据导出。
3. 用户取消或保存失败时，不创建导出任务、不下载文件。
4. 导出请求携带保存成功后的 revision；后台必须确认数据库模板 revision 与请求一致。

模板导出仍允许直接导出未保存草稿，因为它不产生业务结果，也不作为后台任务的稳定输入。

### 2.3 全量与分页

数据导出始终导出当前查询条件下的全部数据，不导出浏览器当前预览页：

- `Full`：后台一次执行完整查询，然后顺序写入结果文件。
- `Paged`：后台按模板配置的稳定页大小逐页查询，直到 `hasMore = false`；所有页面连续写入同一个结果文件。

分页是后台取数和内存控制策略，不改变“导出全部数据”的语义。分页查询必须使用稳定排序，不能跨页重复或遗漏。

## 3. 方案比较

### 3.1 导出浏览器预览快照

优点是改动少，能够复用当前 Univer 预览工作簿。缺点是只能包含当前页，依赖浏览器状态和前端计算结果，无法支持大文件，违反后台重新查询全部数据的既定边界，因此不采用。

### 3.2 继续使用写死导出器

现有 `PocExcelExporter` 可以低内存写入 10 万行，但标题、列、样式和公式均为固定代码，无法反映设计人员保存的模板，因此不采用为最终数据导出实现。

### 3.3 保存模板驱动的后台导出

后台固定模板 revision 和参数快照，根据模板绑定逐页查询全部数据，并使用同一份模板导出计划生成普通或大文件。这一方案满足所见模板、全量数据、稳定任务和性能要求，作为本次实现方案。

## 4. 公式缓存修复

### 4.1 XLSX 导入

`PocXlsxExchangeConverter.ReadCell` 遇到公式单元格时同时写入：

- `f`：以 `=` 开头的 A1 公式文本；
- `v`：XLSX 中可用的缓存值；没有缓存值时写数值 `0`；
- `t`：与缓存值匹配的 Univer 单元格类型，默认数值类型。

缓存结果仍通过现有数据库映射规则的 `TargetPath` 写入，不能绕过 `RcPocExchangeMapping` 把 `v/t` 路径写死。

这会阻止 Univer 在首次载入模板时，因为 `v` 为空而立即用 token 字符串计算公式。公式栏继续显示真实 `f`，模板导出也继续写真实公式，不使用缓存值替代公式。

### 4.2 数据预览

缓存值只服务于设计态显示，不能影响数据预览：

1. 预览副本替换参数并展开明细行。
2. 所有数据和相对公式写入完成后，仅触发一次 `formulaEngine.executeCalculation()`。
3. 等待 `onCalculationResultApplied()` 后再结束渲染计时并开放交互。

这样设计态不显示无意义错误，预览态仍使用 Univer Worker 根据实际数字计算。

### 4.3 Excel/WPS

模板文件和数据文件均设置：

```text
CalculationMode = Auto
ForceFullCalculation = true
FullCalculationOnLoad = true
```

.NET 后台只复制和偏移公式，不计算公式业务结果；Excel/WPS 打开文件后完成最终重算。

## 5. 报表与导出配置

验证契约增加导出设置，后续对应正式库中的 `ExportSettingsJson`：

```json
{
  "defaultMode": "Normal",
  "normalMaxRows": 20000,
  "normalMaxCells": 500000,
  "normalTimeoutSeconds": 60,
  "largeExportEnabled": true,
  "rowsPerSheet": 1000000,
  "fileRetentionHours": 24
}
```

职责分离如下：

- `Preview.Mode` 决定数据源使用完整查询还是分页查询。
- `Export.DefaultMode` 决定同步下载还是异步任务。
- 系统不为了自动猜测模式而预先执行一次昂贵的总数查询。
- 普通模式超过显式上限时返回 `EXPORT_REQUIRES_LARGE_MODE`，不能在同一请求中重新查询并静默切换。

当前 `dept-workload` 数据量为 137 行，默认使用 `Normal`，但因为模板是 `Paged`，后台仍按每页 20 行读取完全部 7 页。

## 6. 后台组件

### 6.1 `PocTemplateDataExportService`

应用服务负责：

1. 根据 `reportCode` 读取数据库模板。
2. 拒绝 revision 0、revision 不一致和损坏绑定。
3. 固定模板快照、规范绑定、查询参数和导出设置。
4. 构造不可变 `PocTemplateDataExportPlan`。
5. 普通模式同步写入响应流；大文件模式把完整计划交给任务存储。

### 6.2 `PocTemplateDataExportPlan`

导出计划只保存稳定输入：

- 报表编码和模板 revision；
- Univer 快照与规范绑定；
- 已解析的参数值；
- 明细工作表、模板行和字段列映射；
- 预览/分页设置和导出设置；
- Univer/Excel 映射版本。

后台任务不能在运行中重新读取“最新模板”，否则创建任务后继续编辑会改变结果。

### 6.3 分页数据枚举器

数据层对导出器暴露顺序页枚举，不暴露前端当前页：

```text
IAsyncEnumerable<IReadOnlyList<PocWorkloadRow>> ReadPagesAsync(...)
```

- `Full` 产生一个批次。
- `Paged` 使用模板页大小循环查询。
- 每页查询沿用同一参数快照和稳定排序。
- 空页或 `hasMore = false` 结束枚举。

验证数据源继续使用固定数据，但必须通过同一页枚举接口，测试能够断言 137 行被分成 `20 * 6 + 17`。

### 6.4 普通模板数据写入器

普通导出使用 ClosedXML：

1. 通过现有 `PocXlsxExchangeConverter` 把保存模板转换为 XLSX 骨架。
2. 根据规范绑定替换参数 token。
3. 在明细模板行位置插入全部数据行并复制样式、行高和公式。
4. 使用 ClosedXML.Parser 的公式转换器按源单元格和目标单元格偏移相对引用，保留绝对引用和跨表引用。
5. 让 ClosedXML 自动移动明细行之后的普通行、合并区域和布局。

普通导出不能复用前端计算结果，也不能保留任何 `{{params.*}}` 或 `{{detail.*}}` token。

### 6.5 大文件模板数据写入器

大文件导出继续使用 `ZipArchive + XmlWriter`，避免把全部行放进 ClosedXML 内存模型：

1. 先生成只有模板结构的 XLSX 骨架。
2. 原样复制工作簿、样式、主题和非目标工作表部件。
3. 目标工作表使用前向 XML 写入器重写。
4. 模板行之前的内容直接复制并替换参数。
5. 每读取一页数据立即克隆明细模板行并写入，不保存历史页面。
6. 使用 ClosedXML.Parser `FormulaConverter` 调整每行公式引用，不使用正则表达式修改公式。
7. 明细区域之后的行、合并区域和坐标按新增行数平移。
8. 定期更新已写行数，支持取消；失败或取消删除半成品。

普通和大文件写入器消费同一个导出计划和页枚举器，区别只有工作簿构造方式。

## 7. HTTP 契约

### 7.1 普通数据导出

```text
POST /api/report-center/poc/{reportCode}/exports/normal
```

请求：

```json
{
  "templateRevision": 4,
  "query": {
    "page": 1,
    "hospitalId": "H01",
    "deptId": "D02",
    "personId": "P03",
    "startDate": "2026-07-01",
    "endDate": "2026-07-15"
  }
}
```

后台忽略 `query.page` 的当前页含义，从第一页开始读取全部数据。成功返回 XLSX 文件流。

### 7.2 大文件任务

```text
POST /api/report-center/poc/{reportCode}/exports/large
GET  /api/report-center/poc/export-jobs/{jobNo}
POST /api/report-center/poc/export-jobs/{jobNo}/cancel
GET  /api/report-center/poc/export-jobs/{jobNo}/download
```

创建任务请求同样包含 `templateRevision + query`。任务创建时立即冻结导出计划，随后返回 `jobNo`。状态接口继续返回总行数未知时可用的已写行数；验证数据源可以返回确定总数。

## 8. 页面交互

命令栏显示：

- 设计模式：`导入模板`、`导出模板`、`导出数据`、`保存模板`。
- 预览模式：`导出数据`；模板导入导出仍只在设计模式显示。

“导出数据”流程：

1. 检查当前模板是否 dirty 或 revision 0。
2. 需要保存时显示“当前模板尚未保存，是否保存后继续导出数据？”。
3. 确认后保存设计草稿；在预览模式使用进入预览前保留的设计草稿保存，不保存数据副本。
4. 根据 `definition.export.defaultMode` 调用普通下载或创建大文件任务。
5. 大文件任务显示已写行数，完成后自动下载；失败和取消保留明确状态。

导出期间禁止重复保存、预览、导入和再次导出，但不冻结整个浏览器页面。

## 9. 错误语义

新增或复用稳定错误码：

| 错误码 | 含义 |
| --- | --- |
| `TEMPLATE_SAVE_REQUIRED` | 数据导出没有可用的已保存模板 |
| `TEMPLATE_REVISION_CONFLICT` | 请求 revision 已过期 |
| `EXPORT_REQUIRES_LARGE_MODE` | 普通导出超过模板限制 |
| `EXPORT_PAGING_ORDER_REQUIRED` | 分页数据集缺少稳定排序 |
| `EXPORT_TEMPLATE_BINDING_INVALID` | 保存模板不能生成数据导出计划 |
| `EXPORT_JOB_NOT_READY` | 大文件尚未完成 |
| `EXPORT_JOB_FAILED` | 大文件任务失败 |

保存、普通导出或任务创建任一步失败，都不得下载空文件或错误 JSON 冒充 XLSX。

## 10. 测试策略

### 10.1 公式缓存

- 导入有缓存值的公式时保留缓存类型和值。
- 导入无缓存值公式时得到 `f`、`v = 0` 和数值 `t`。
- 公式、样式和映射路径仍可由数据库规则影响。
- 浏览器载入导入模板时不显示 `#VALUE!`。
- 进入预览后显式重算，`C6 + D6` 得到实际数字。

### 10.2 普通数据导出

- revision 0 和旧 revision 被拒绝。
- Paged 模板读取全部 7 页并导出 137 行，而不是当前 20 行。
- 参数 token、明细 token 在结果文件中全部消失。
- 标题、样式、合并、行高、列宽、冻结区域保持。
- 明细公式从模板行正确偏移到首行、第二行和末行。
- 文件设置 Excel/WPS 打开重算。

### 10.3 大文件导出

- 10 万行按页读取并持续更新进度。
- 写入器不保存全部行集合，取消和失败删除半成品。
- 末行公式引用正确，文件可由 ClosedXML/Open XML SDK 重新打开。
- 运行时内存继续记录并与现有约 62 MB 增量基线比较。

### 10.4 页面

- dirty 和 revision 0 会先请求保存确认。
- 取消确认不保存、不导出。
- 保存失败不调用导出接口。
- 保存成功使用新 revision 发起导出。
- 普通模式直接下载；大文件模式轮询后下载。
- 浏览器实际验证模板导出、数据导出和移动视口无重叠。

## 11. 验收标准

1. 导入当前 XLSX 模板后，设计态公式单元格不再显示 `#VALUE!`，公式栏仍是原始公式。
2. 预览 20 行时 Univer Worker 使用实际数据计算公式，缓存值不会污染结果。
3. “导出模板”文件保留 token；“导出数据”文件不含任何 token。
4. 当前 Paged 报表的数据导出包含全部 137 行，不是浏览器当前页。
5. 未保存模板必须确认并保存成功后才能导出数据。
6. 普通和大文件导出都读取固定 revision 的保存模板并保留公式、样式和布局。
7. 大文件分页查询和前向写入不把全部结果加载到内存。

## 12. 本轮不处理

- 后台计算或缓存最终公式业务结果。
- 跨拆分工作表的全局公式重写。
- 多个明细数据集、嵌套循环、分组小计和交叉表。
- 图片、图表、批注、数据透视表和宏。
- 用浏览器当前预览页替代后台全量查询。
