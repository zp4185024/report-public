# 可编辑报表模板核心验证设计

日期：2026-07-14  
状态：已确认，待实施计划  
适用范围：`ReportWeb` 与 `HD.ReportCenter` 核心验证工程

## 1. 背景

现有核心验证已经证明以下能力可用：

- .NET 8 后台能够提供报表定义、分页数据和 Excel 导出。
- Univer OSS 能够在浏览器中渲染工作簿，并在 Web Worker 中计算公式。
- 普通导出和十万行大文件导出的基本性能达到验证目标。

但是，当前工作簿的标题、参数单元格、明细列和公式都写死在前端代码中。接口返回数据后，前端直接覆盖固定区域。这只能证明“显示结果”，不能证明真正的报表工作流：设计人员编辑模板、绑定后台字段、立即预览实际数据、保存后重新加载。

本轮验证修正这一缺口。它不是完整模板平台，而是一个最小但真实的“模板编辑 -> 数据绑定 -> 预览 -> 恢复编辑 -> 保存重载”闭环。

## 2. 目标与判定标准

本轮只回答一个关键问题：

> 使用 Univer OSS，能否快速实现可编辑的报表模板，并将 .NET 8 后台返回的参数和明细数据绑定到模板，同时保留样式和相对公式？

验证成功必须同时满足：

1. 设计人员可以在 Univer 中修改标题、单元格内容、样式、合并和公式。
2. 设计人员可以选中单元格后点击字段完成绑定，也可以直接输入占位符。
3. 不保存模板也能用当前草稿预览后台实际测试数据。
4. 一个明细模板行可以展开为多条数据，样式、行高、数字格式和公式随行复制。
5. 相对公式随目标行自动偏移，并由 Univer Worker 计算出预览结果。
6. 从预览返回设计后，占位符和原始模板公式仍然存在，不被预览数据覆盖。
7. 保存模板后刷新页面，数据库中的模板快照和绑定关系能够恢复。

任何一项缺失，都不能宣称模板技术路线验证完成。

## 3. 已确认的范围

### 3.1 本轮实现

- 使用同一块 Univer 画布，在“模板设计”和“数据预览”两种模式之间切换。
- 开启 Univer OSS 的工具栏、公式栏、行列头、右键菜单和工作表栏。
- 提供固定参数字段和固定明细数据集字段。
- 支持点击字段绑定和直接输入占位符两种方式。
- 支持任意参数单元格和一个连续的明细模板行。
- 预览使用现有 .NET 8 接口返回的真实测试数据，当前验证继续使用每页 20 行。
- 使用一条数据库模板记录验证保存、刷新和重新加载。
- 保留现有公式 Worker，验证明细行公式计算。

### 3.2 本轮不实现

- Excel 模板导入。
- 多个明细数据集、多个明细区域、分组、小计、交叉表和嵌套循环。
- 模板版本、发布、复制、权限和协作。
- 图表、图片、批注和高级条件格式。
- 将当前模板直接用于普通或大文件导出。
- 模板之外的统计计算。

导出入口在本轮模板编辑页面中暂时隐藏，避免让用户误以为导出已经使用当前编辑模板。后续必须让普通导出和大文件导出共同读取已发布的同一份模板快照，不能继续使用现有写死的导出结构。

## 4. 用户操作流程

### 4.1 页面加载

1. 页面读取固定报表 `dept-workload` 的模板记录。
2. 数据库已有记录时加载其 `SnapshotJson`；没有记录时，后台返回一份种子模板。
3. 页面默认进入“模板设计”模式。
4. URL 中的 `hospitalId`、`deptId`、`personId` 等参数继续作为本次预览输入；日期默认值继续由后台报表定义解析。

### 4.2 模板设计

页面顶部提供“模板设计 / 数据预览”分段切换和“保存模板”命令。设计模式左侧显示字段面板，右侧是 Univer 编辑画布。

字段面板分为两组：

- 查询参数：`hospitalId`、`deptId`、`personId`、`startDate`、`endDate`。
- 明细字段：`sequence`、`departmentName`、`outpatientCount`、`dischargeCount`。

设计人员选中单元格后点击字段：

- 参数字段写入 `{{params.hospitalId}}` 形式的占位符。空单元格直接写入；普通文本单元格在末尾追加；公式单元格拒绝写入并提示先选择普通单元格。
- 明细字段用 `{{detail.departmentName}}` 形式的占位符替换当前单元格内容，确保占位符独占单元格。
- 直接在单元格或公式栏输入同样的占位符也有效。

参数占位符可以嵌入固定文本，例如：

```text
医院：{{params.hospitalId}}
统计期间：{{params.startDate}} 至 {{params.endDate}}
```

明细占位符必须独占一个单元格，不能与固定文字混写。这样绑定后的数字仍是数字，能够正确使用数字格式和参与公式计算。

### 4.3 数据预览

切换到“数据预览”时执行以下流程：

1. 从当前 Univer 工作簿取得最新快照，保存为内存中的 `draftSnapshot`。
2. 扫描并校验占位符，生成本次预览的绑定描述。
3. 调用现有 `execute` 接口，后台解析 URL 参数、日期默认值并返回当前页数据。
4. 深度克隆 `draftSnapshot`，并将克隆加载为同一个 Univer 宿主中的预览工作簿。
5. 根据绑定描述生成执行计划，由 Univer 在预览工作簿中替换参数、插入明细行、复制模板行并写入字段值。
6. Univer Worker 计算展开后的公式，并将当前预览工作簿视为 `previewSnapshot`。
7. 预览模式关闭编辑能力和字段面板，只显示结果与返回设计入口。

切回“模板设计”时重新加载 `draftSnapshot`，不从预览工作簿反向提取数据。因此后台数据和展开后的行不会污染模板。

### 4.4 保存与重载

“保存模板”只在设计模式可用。保存前重新读取当前工作簿快照并扫描绑定，然后一次提交：

- `SnapshotJson`：保留占位符的 Univer `IWorkbookData`。
- `BindingJson`：由占位符扫描得到的参数和明细绑定。
- `Revision`：用于阻止两个旧页面互相覆盖。

保存成功后更新当前修订号。发生修订冲突时不自动覆盖数据库，页面提示用户刷新后重试。这个轻量控制足以验证内部系统的模板持久化，不引入完整发布流程。

## 5. 绑定规则

### 5.1 参数绑定

- 参数占位符可以出现在任意工作表、任意单元格。
- 一个单元格可以包含固定文本和多个参数占位符。
- 未知参数、括号不闭合或空字段名属于模板错误，禁止预览和保存。
- 参数替换只产生值或展示文本，不参与 SQL 拼接；SQL 参数仍由后台按定义绑定。

### 5.2 明细绑定

- 整个工作簿只能有一个包含 `{{detail.*}}` 的模板行。
- 同一模板行可以有多个明细字段，也可以有普通文本和公式单元格。
- 每个明细字段占位符必须独占单元格。
- 明细字段必须存在于固定数据集定义中。
- 没有明细占位符时允许只预览参数型模板，但不会展开数据行。
- 明细模板行不能包含合并单元格；模板其它区域仍然支持合并。
- 出现第二个明细模板行、合并区域跨越明细行边界或明细行内存在不支持结构时，返回明确的模板校验错误。

### 5.3 行复制与公式

明细数据有 N 行时，预览结果中保留 N 份模板行。每份包含：

- 原模板行的单元格样式、行高、边框、数字格式和公式。
- 当前数据行对应的字段值。
- 按目标行偏移后的相对公式引用；绝对引用保持不变。

首选实现是复用 Univer OSS 已有的行插入和复制/填充命令，让 Univer 自身处理公式引用偏移。本轮不编写通用 Excel 公式解析器。若当前 OSS 版本无法通过公开或稳定能力完成公式偏移，则本项验证判定失败或需要先升级 Univer 版本，不能用脆弱的字符串替换掩盖风险。

验证模板至少包含以下公式：

```text
=C6+D6
=AVERAGE(C6:D6)
```

展开后下一行必须自动成为 `=C7+D7` 和 `=AVERAGE(C7:D7)`，并显示正确计算结果。

## 6. 前端结构

前端按职责拆为以下单元：

| 单元 | 职责 |
|---|---|
| `TemplateEditorPage` | 管理加载、模式切换、参数、保存和错误状态 |
| `TemplateFieldPanel` | 展示可绑定字段，将选中字段写入当前单元格 |
| `UniverTemplateHost` | 创建一次 Univer 运行时，加载设计或预览工作簿，暴露快照和选区操作 |
| `templateBindingScanner` | 从快照扫描占位符，产生结构化绑定和校验错误 |
| `templatePreviewPlanner` | 根据绑定和后台结果生成参数替换、明细插行、行复制和字段写入计划 |
| `templateApi` | 读取和保存模板，复用现有执行接口获取预览数据 |

`TemplateEditorPage` 不直接读写单元格数据。绑定扫描和预览计划生成保持为无界面的纯逻辑，便于单元测试；`UniverTemplateHost` 封装第三方 API，并负责在克隆工作簿上执行计划。这样既隔离 Univer 细节，也确保公式偏移实际由 Univer 完成。

同一页面只保留一个活跃 Univer 运行时和一个 Worker。切换模式时替换工作簿内容，不并排创建两个大型画布，减少内存、事件监听和状态同步成本。

## 7. 后台与数据库

### 7.1 POC 模板记录

新增一张仅供核心验证使用的表 `RcPocReportTemplate`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `Id` | bigint | 主键 |
| `ReportCode` | nvarchar(64) | 唯一报表编码，本轮固定为 `dept-workload` |
| `SnapshotJson` | nvarchar(max) | 保留占位符的 Univer 工作簿快照 |
| `BindingJson` | nvarchar(max) | 扫描后生成的结构化绑定 |
| `Revision` | int | 乐观并发修订号 |
| `CreatedTime` | datetime2 | 创建时间 |
| `UpdatedTime` | datetime2 | 最后更新时间 |

该模型可以在当前验证使用的 SQLite 和后续 SQL Server 上保持相同语义。正式迁移时再合并到总体设计中的 `RcReportVersion`，本轮不提前实现版本发布模型。

### 7.2 接口

```http
GET /api/report-center/poc/dept-workload/template
PUT /api/report-center/poc/dept-workload/template
POST /api/report-center/poc/dept-workload/execute
```

`GET template` 返回：

```json
{
  "reportCode": "dept-workload",
  "snapshot": {},
  "binding": {},
  "revision": 1
}
```

`PUT template` 接收同样的数据结构，并返回包含新修订号的已保存对象。后台校验报表编码、JSON 可反序列化、内容大小和修订号后，在一个事务内新增或更新记录。后台不信任前端生成的 `BindingJson`：至少重新校验绑定字段名和唯一明细行约束，再写入数据库。

`BindingJson` 使用固定版本结构，坐标为从零开始的行列索引；同一参数在多个单元格出现时保存多条绑定：

```json
{
  "version": 1,
  "parameterBindings": [
    {
      "code": "hospitalId",
      "sheetId": "report-sheet",
      "row": 1,
      "column": 0
    }
  ],
  "detailBinding": {
    "datasetCode": "detail",
    "sheetId": "report-sheet",
    "templateRow": 5,
    "fields": [
      {
        "code": "departmentName",
        "column": 1
      }
    ]
  }
}
```

`BindingJson` 是从模板占位符派生的持久化索引，不提供单独的手工 JSON 编辑入口。读取模板时仍以 `SnapshotJson` 中的占位符为事实来源；两者不一致时拒绝加载并提示模板数据损坏。

现有 `execute` 接口保持后台数据查询和业务数据准备职责，返回解析后的参数与明细行。模板展开和当前页公式求值发生在前端，这与 Univer 的工作方式一致。

## 8. 状态与错误处理

页面需要清楚区分以下状态：

- 模板加载中或加载失败。
- 设计草稿有未保存修改。
- 正在生成预览或后台查询失败。
- 占位符或明细区域校验失败。
- 模板保存中、保存成功或修订冲突。
- Univer 公式计算错误。

预览失败时继续保留 `draftSnapshot` 并返回设计模式，不清空用户修改。保存失败时同样保留当前草稿。错误提示必须指明工作表和单元格，例如“报表!B6 使用了未知字段 `detail.amount`”。

离开页面且存在未保存修改时使用浏览器离开确认。本轮不实现自动保存。

## 9. 性能约束

本轮仍使用当前页 20 条数据，目标不是大数据预览，而是避免模板切换引入明显退化：

- Univer 运行时和 Worker 在页面生命周期内只创建一次。
- 模式切换不重新下载依赖，不创建第二个 Univer 实例。
- 快照仅在进入预览、返回设计和保存时读取，不在每次单元格编辑时序列化。
- 参数替换和 20 行明细展开在普通办公电脑上应低于 50ms。
- 从点击预览到公式结果可见，在不计后台查询的情况下应低于 300ms。

后续完整预览或大数据导出继续遵守总体设计：是否分页由模板定义；几万行数据不在前端完整展示；Excel 公式由导出文件打开后计算。

## 10. 测试方案

### 10.1 前端单元测试

- 扫描纯参数占位符和嵌入文本的参数占位符。
- 拒绝未知字段、错误语法、第二个明细行和混写的明细占位符。
- 用一条明细生成一行，用多条明细展开多行。
- 绑定数值后保持数值类型和模板数字格式。
- 预览构建不修改原始设计快照。

### 10.2 后台测试

- 无数据库记录时返回种子模板。
- 首次保存后可重新读取相同快照和绑定。
- 修订号正确递增，旧修订保存返回冲突。
- 拒绝未知报表编码、超限 JSON 和非法绑定字段。

### 10.3 浏览器端到端验证

按真实用户路径验证：

1. 打开页面，进入模板设计。
2. 修改标题、背景色和一个数字格式。
3. 选中参数单元格并点击 `hospitalId`。
4. 在唯一明细行绑定四个字段，并输入两个公式。
5. 不保存直接进入预览。
6. 确认 URL/后台参数、20 行实际测试数据和公式结果可见。
7. 确认第二条数据的公式引用从第 6 行偏移到第 7 行。
8. 返回设计，确认占位符和原始公式未被数据覆盖。
9. 保存并刷新，确认修改后的标题、样式、公式和绑定全部恢复。
10. 在桌面视口检查无控制重叠，并确认浏览器控制台无错误。

## 11. 完成定义

本轮完成后，演示页面必须让用户亲手完成以下闭环：

> 编辑一个真实 Univer 模板 -> 绑定后台参数和明细字段 -> 立即预览分页测试数据和公式结果 -> 返回继续编辑 -> 保存 -> 刷新后恢复。

只有这一闭环和自动化测试都通过，才能进入 Excel 模板导入、模板发布，以及普通/大文件导出统一使用模板的下一阶段。
